## 1. Current State

### What the project does

cv-healthcheck is a Flask + FastMCP application that produces customer-facing health-check snapshots for Commvault environments. It collects evidence three ways — live REST (Command Center API, Reports Plus), uploaded exports (HTML/CSV/XLSX), and (future) S3-transported snapshots — normalizes everything into a single Pydantic v2 canonical artifact contract, and renders a customer-facing report.

The product is organised around three operating modes:
- **Daily Reporting** — recurring operational reporting from Reports Plus/Metrics (future).
- **Quick HealthCheck** — fast, low-impact assessment from Reports Plus, REST snapshots, and uploaded artifacts (current focus).
- **Full HealthCheck** — comprehensive evidence-driven analysis (future).

### Stack

- Python 3.11+, Flask, Jinja2
- Pydantic v2 (canonical artifact schema, frozen)
- SQLite (raw SQL — no ORM)
- BeautifulSoup4 (HTML extraction)
- Click (CLI), FastMCP (MCP server)
- Vanilla JS + Chart.js for the Quick HC frontend

### Entry points

- `cv-healthcheck` → `cvhealthcheck.cli:main` (CLI + Flask dev server via `start.sh`)
- `cv-healthcheck-mcp` → `cvhealthcheck.mcp.server:main` (MCP server)
- HTTP UI: `http://127.0.0.1:5001/quick-hc`

### What is working and verified

- **Quick HC overview UI** (`/quick-hc`) — standalone dark UI with sidebar (Subjects grouped by category), main panel (Description / Data Source / Report Sections), action bar at the bottom of the main panel that appears when subjects are selected.
- **Sidebar subject catalog** — DB-driven via `get_tiles(db)`. Shows 8 active subjects: CommCell Details, Security Assessment, License Summary, Client Growth, Capacity Licenses, Backup Job Summary, plus two AI-created subjects (Cloud Storage Egress & Ingress, Storage Utilization).
- **Canonical artifact pipeline** — `ArtifactStore` reads `data/catalog/artifacts/<subject>/latest.json`; `build_subject_initial_data()` always prefers canonical over legacy.
- **Subject display name override** — `subject_data_service.py:213` forces `view["name"] = tile["title"]` so the registry/DB title wins over `artifact.subject.title` (which may be stale provenance from old test imports).
- **Connection badge** — shows `Connect` when not authenticated, `Connected` when authenticated (no more "6 available" bug).
- **HTML extractor section matching** — accepts both exact match and `"<title> -"` / `"<title>:"` prefix forms, so `"Other Licenses - current usage details"` matches the `"Other Licenses"` instruction.
- **Security Assessment / License Summary imports** — `/quick-hc/security-assessment/import` and `/quick-hc/license-summary/import` write both legacy artifact and canonical artifact.
- **Generic upload import** — `/quick-hc/import?subject_id=<id>` routes through `extract_file()` → `result_to_artifact()` → `ArtifactStore.save_artifact()`.
- **Customer-facing report** — `/quick-hc/report` (GET = default, POST = with `selection_ids[]`) renders only selected subjects/sections; strips artifact paths, dataset GUIDs, HTTP statuses.
- **Report action bar** — fixed at the bottom of the main panel; visibility driven by "Include in report" toggles; POSTs `selection_ids[]` to `/quick-hc/report`.
- **MCP server** — exposes `list_subjects`, `propose_new_subject`, `list_proposed_subjects`, `save_staged_artifact`, `list_staged_artifacts`, `approve_staged_artifact`, `reject_staged_artifact`, `get_canonical_schema`. AI-proposed subjects flow through `staged_artifacts` → `execute_approval` → `subjects` table.
- **Staging review UI** — `/quick-hc/staging` lists pending proposals; approve/reject flows through `execute_approval()`.
- **Test isolation fix** — `execute_approval()` now accepts an injectable `ArtifactStore` so tests no longer pollute the real `data/catalog/artifacts/security_assessment/latest.json` (this had been writing "Test Subject" data on every `pytest` run).
- **Test count: 461 passing.** Suite runs in under 3 seconds.

### What is partially working or known broken

- **Section ID double-prefix** — `canonical_view.artifact_to_view()` builds `sec_id = f"{subject_id}.{sec.id}"` but the HTML extractor already stores fully-qualified section IDs (`security_assessment.access_security`). Result: rendered section IDs like `security_assessment.security_assessment.access_security`. Display titles are correct; only the IDs are mangled. Affects URL-fragment routing and localStorage section keys.
- **Legacy `data/catalog/<subject>/latest.json` still exists** alongside the canonical `data/catalog/artifacts/<subject>/latest.json`. The legacy path is used by `security_assessment_quick_hc()` for legacy fallback. Two stores of truth for the same data is a migration debt.
- **Quick HealthCheck Report nav item** — "Reports" link in the sidebar points to `/quick-hc/report` (GET, default selections). The Generate Report button POSTs selected IDs to the same route. Both work, but the relationship is non-obvious.
- **`shared.py` god module** — still imports from 15+ service modules and houses preview helpers; documented in `docs/review_2026-05-20.md` but not yet refactored.
- **Hardcoded detail URLs in `report_service.py`** — `_build_*_section()` methods still contain literal `/quick-hc/<subject>` strings instead of resolving via `TileDefinition.detail_endpoint`. Flagged in 2026-05-20 review.
- **Stale test pollution artifacts** — ~18 timestamped 955-byte JSON files in `data/catalog/artifacts/security_assessment/` from before the `execute_approval` fix. Inert (only `latest.json` is loaded). Can be cleaned with: `find data/catalog/artifacts/security_assessment -size 955c -delete`.
- **`data/app.db` is committed and tracked** — local state ends up in the repo. Should be in `.gitignore` or regenerated by migrations on first run.
- **`HANDOVER_TO_CODE.md` and `migrations.py` / `0003_report_inventory.sql`** are duplicated at the project root and in `src/cvhealthcheck/db/migrations/`. The root copies are stale design artifacts.

## 3. Open Issues

### High priority

1. **Section ID double-prefix in `canonical_view.artifact_to_view()`** (`src/cvhealthcheck/quickhc/canonical_view.py:116`).
   Fix: detect whether `sec.id` already starts with `f"{subject_id}."` and skip the prefix in that case.
   Why: section IDs leak into the JS state, the rendered HTML, and the localStorage key. Mismatched IDs between the registry and the rendered view break per-section include/exclude state and the URL fragment selection contract.

The UI reads from canonical, the legacy path is still written by `import_security_assessment_upload` and friends. Fix: stop writing the legacy path, OR add a one-way migration on startup that imports the legacy file into the canonical store on first run.
